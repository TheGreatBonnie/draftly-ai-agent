Implementation Approaches

How should we structure the code?

Approach 1: Minimal Refactor

Keep existing ReviewDetail.tsx as-is. Add loading skeleton, error states, back nav, markdown rendering, expandable form, and confidence comparison inline.

+ Fastest to implement - Component will grow to 300+ lines - Harder to test individual pieces

Approach 2: Hybrid (Recommended)

Keep ReviewDetail.tsx as the container. Extract sub-components: ReviewHeader, ReviewContent, ReviewForm, ConfidenceComparison. Each component has a single responsibility.

+ Clean separation of concerns + Easier to test and maintain - Slightly more files to create

Approach 3: Full Rewrite

Start from scratch. Create all new components with a fresh architecture. Ignore existing code entirely.

+ Cleanest architecture - Most work, highest risk - May lose existing working logic
