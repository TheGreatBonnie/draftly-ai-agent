How to fix CORS errors in production

troubleshooting published Version 2 · Updated Jul 24, 2026

CORS (Cross-Origin Resource Sharing) errors occur when a server doesn't include the proper headers in its response. This is one of the most common issues when integrating Draftly with external services.

Common Causes

There are several reasons CORS errors appear in production:

  • Missing header — The production server doesn't include Access-Control-Allow-Origin
  • Wildcard with credentials — Using * origin when credentials are required
  • Preflight timeout — OPTIONS requests taking too long to respond
  • Wrong Content-Type — Missing application/json in allowed headers

Solution for Node.js/Express

Add the CORS middleware to your Express app:

const cors = require('cors'); app.use(cors({ origin: process.env.ALLOWED_ORIGINS?.split(','), credentials: true, methods: ['GET', 'POST', 'OPTIONS'], allowedHeaders: ['Content-Type', 'Authorization'] }));

Environment Variables

Set the following in your .env file:

ALLOWED_ORIGINS=https://app.draftly.ai,https://draftly.ai CORS_CREDENTIALS=true

Testing

Use curl to verify your CORS configuration:

curl -I -X OPTIONS \ -H "Origin: https://app.draftly.ai" \ -H "Access-Control-Request-Method: POST" \ https://api.yourdomain.com/webhook

You should see Access-Control-Allow-Origin in the response headers.
